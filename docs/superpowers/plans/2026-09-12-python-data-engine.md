# Python 数据引擎首版

用户要求强化多维数据分析与采集，加入Python。保留已授权的自动发现主流程，无需提供主题。增加Python而非全站迁移：Node保留数据库/任务租约/接口，Python作为无状态内部计算与采集模块，React展示分析依据。

- FastAPI两个接口：POST /analyze 对本轮全部合格材料处理，POST /collect 采集App Store评论。HTTP只在Docker内部，开发可单独启动。Pydantic输入限制、请求超时、来源固定域名与错误隔离。
- Polars统计来源分布，scikit-learn TF-IDF字符特征与余弦相似度分组。明确是文本相似，不冒充跨语言语义理解。输出重复内容、来源账号、渠道、近期性、痛点/价格/替代方案摩擦线索等。商业价值、获客、工期等没有依据时仍未知。
- 数据库新增RADAR_ANALYZE任务与radar_scans.analytics。collecting后排队Python分析；保存结果并按文本组分批提取，所有合格材料仍进入处理。调用不在DB事务内，保存与job完成同一租约事务。失败不假装完成分析。
- 模型汇总收到Python计算指标、限制与来源ID；最终推荐关联这些指标以便比较。证据优先级不能称商业成功概率。
- AppStore为第4个自动渠道，Apple Search选最多2应用，每应用最近20评论，一轮4查询最多160评论；公开接口可能限流/无结果，部分失败必须呈现。保留评分、应用、国家、原文链接。美国市场的评论不作为亚洲/欧洲/中东证据。
- 首页展示多维证据分组，用户无需参与分类。无机会报告时也可看到实际分析，不把几个LLM调用称为强数据分析。
- Python单元测试（去重/相似度/日期/缺失值/采集安全/响应限制）；TS跨模块及任务状态测试；Docker真实采集和全链路分析；浏览器可读性与溢出检查。

当前首版不引入Airflow/Celery/Redis第二套调度，不自动开始定时运行，不新增付费数据订阅；用户当前任务授权范围内实现可运行闭环。

实测调整：Apple公开评论持续为空，新增WordPress官方插件评价作为第5渠道。每轮20个查询任务、最多680份返回材料，实际未必达到上限。WordPress显示名不当作已验证账号。加入完整正文指纹与保守复制来源/时间计数；有报告时统计默认折叠。详见docs/python-data-engine.md与verification.md。
