# 来源覆盖与机会优先级

目标：回答当前数据来自哪里、为什么机会少、多个假设中先验证哪一个。沿用机会与证据模型，不将模型估值当成市场事实。

1. `packages/opportunities/src/comparison.ts`：加载全部未放弃机会（上限30，超过时显式拒绝而非静默抽样）及当前 founder、声明审核状态；模型返回五维1–5或未知、理由和下一步验证。纯函数计算已知维度加权比较分及覆盖率，不把未知当0；低覆盖不排序。资料变更以输入hash检测失效。
2. 迁移008存储独立比较快照，COMPARE_OPPORTUNITIES后台任务通过租约原子提交。API GET/POST comparison、workspace来源统计。比较不修改机会、不接受声明；重复任务复用。
3. React比较页并列评分、理由、缺口及建议动作；显式“暂定验证顺序”，非开发推荐。来源面板展示官网/HN实际数量和Reddit未配置状态；保持现有原文入口。
4. 测试缺失值、排序、过期输入、租约与API行为；真实12机会模型运行，桌面/手机验证，Docker部署与提交。

权重：需求25%、付费价值25%、开发可行性20%、获客15%、个人匹配15%。均为高分更有利；模型估计与人工审核状态独立显示。仅已知权重覆盖>=60%且至少三个维度有值才提供比较分；已知加权均值四舍五入到0.1/5。分数不是成功概率。无founder输入时匹配强制未知。

本次不声称新增外部来源。来源扩展需围绕明确目标用户/产品配置；当前仅3个产品、85条HN讨论，扩展参考产品池与需求主题搜索是下一步。

验收补充：模型第一轮误将已有非营利折扣评高。新增结构化差异检查（distinct/overlap/unknown）；overlap不计算综合排名，无未排除痛点声明时需求最高2分；不得假设拥有第三方平台。模型规则版本参与过期检测。
