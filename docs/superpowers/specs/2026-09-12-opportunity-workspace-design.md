# 独立开发者机会工作台重写

用户已要求按复核结论重新设计并重写。选择保留可靠输入层、替换业务核心与首页的方案；完全删库重来会丢证据，仅改页面不能解决模型缺失。原文和已有翻译保留。

业务：参考产品 -> 带原文的声明 -> 机会草稿 -> 人工核对市场与需求证据 -> 候选 -> WATCH / VALIDATE / KILL。机会以付费人群、任务、具体切口、最小方案、收入假设、获客计划、工期/维护/风险、最大未知和验证条件表达。没有证据的字段保持未知。AI 只提出草稿，不自动认证或打分。

数据库追加 evidence_claims、opportunities、opportunity_claims、opportunity_decisions；参考产品沿用旧表以兼容历史关联，但取消域名唯一约束，人工创建支持独立 ID。证据声明必须对应快照的精确摘录，带 market/pain/revenue/distribution 分类和 pending/accepted/rejected 审核；每个机会关联有独立审核状态。候选门槛为至少一个 accepted market/revenue 及一个 accepted pain，且有参考产品；拒绝证据后动态降级。决策记录不可覆盖，VALIDATE 必须有预算/期限/成功/终止条件。维度和假设在结构化 dossier JSON 内，证据关系与决策独立存表。

AI 研究：按产品选取最新关联源快照（最多 6 篇，每篇 12000 字符，明确截断），编号原文行提取声明，然后生成机会假设并只允许关联本次已提取的声明 ID。计划与推测必须保持推断标签。复用模型配置和后台队列，提供 ANALYZE_PRODUCT，幂等防止重复点击重复付费，租约 fencing 后事务提交。重做使用新的任务键，不覆盖历史决策。研究即使缺少需求也生成可补证的草稿，不编造痛点。

界面中文：机会为首页，草稿/候选/已放弃筛选，详情展示具体方案、证据审阅、验证计划、决策时间线。参考产品页可导入官网/手动补充研究材料并发起研究；原文库保留翻译。设置保存 founder 约束并在每次研究中使用，机会保存当时配置。系统公开覆盖缺失和失败状态，无假数据。

验收：自动测试通过证据精确性、动态准入、决策验证、队列原子提交、模型越界引用拒绝；浏览器验证研究到审阅到决策流程；真实产品研究只能形成草稿，不伪称需求已证实。生产数据只读备份后追加迁移。
